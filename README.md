# 跳过广告 · AdSkipper

免 root 的安卓去广告工具，只针对 **三星（One UI）** 和 **一加（ColorOS / OxygenOS）** 做过适配。安全优先：不采集、不上传、无第三方 SDK，屏幕文字只在内存里做匹配。

**v1.2** ｜ `versionCode 3` ｜ 三星 One UI · 一加 ColorOS ｜ 免 root ｜ 不采集数据

> **支持范围**：三星（One UI）与一加（ColorOS / OxygenOS）是适配目标。OPPO / realme 和一加同源，大概率能跑，但**没适配、不保证**；小米 / 华为 / vivo / 荣耀等其它品牌同理——能跳是运气，跳不了不是 bug。

## 安全与权限边界（先看这个）

| 项 | 事实 |
|---|---|
| 权限 | 只有 **5 条** `uses-permission`：`INTERNET`（只给 DNS 层转发查询用）、`FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_SPECIAL_USE`（DNS 层常驻要带通知）、`POST_NOTIFICATIONS`（显示那条通知）、`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`（防止被系统杀）。另外两个 `BIND_*` 是系统对「无障碍服务 / 通知监听」自己的强制要求 |
| 没有申请的权限 | 定位、通讯录、短信、通话记录、相机、麦克风、存储读写、悬浮窗、读取设备标识（IMEI / Android ID / OAID）、后台自启——一条都没有，`AndroidManifest.xml` 可以逐条核对 |
| 采集 / 上传 | 不采集、不上传。没有第三方 SDK、没有埋点、没有统计、没有崩溃上报（`app/build.gradle.kts` 零第三方依赖）；DNS 层关掉时整个 App 不发任何网络请求 |
| 屏幕内容 | 只把当前窗口里的控件文字读出来跑正则，命中「跳过 / 关闭」就点一下；**不保存、不截图、不上传**。日志只在内存里（环形最多 400 条，重启即清空，不落盘） |
| DNS 层 | 只处理 UDP/53 的域名查询，命中黑名单回 NXDOMAIN，**不抓 HTTP、不读正文**；上游是硬编码的公共 DNS（223.5.5.5 / 119.29.29.29 / 180.76.76.76），**上游仍然能看到你查了哪些域名**——任何 DNS 方案都绕不开这点，介意就别开这层 |
| 代码可自审 | 零第三方依赖、`isMinifyEnabled=false`，构建产物和源码一一对应，几十个 Kotlin 文件可以自己从头读一遍 |
| 能力边界（诚实说） | 无障碍 API 技术上**能读到焦点窗口里的任意文字**（包括密码框），这是权限本身的范围，不是本 App 额外多要的。不想让它碰敏感界面：把银行 / 支付 / 证券 / 密码管理器的包名填进「不处理的应用（黑名单）」 |
| 不做什么 | 不 root、不注入、不反编译、不修改任何第三方 App、不绕过付费墙 |

> 一句话：读屏权限本身很大（这类工具的宿命），但**所有东西都留在你手机上**——除了你主动打开 DNS 层时的那几次域名查询。

**本版新增（v1.2）**

- **适配一加（ColorOS / OxygenOS）**：桌面（HOME）和输入法包名改成从 `PackageManager` 动态读取——三星 / 一加的桌面与输入法自动排除，换了桌面也能跟上；静态列表再兜底 ColorOS / OxygenOS 的桌面、状态栏、安全中心、输入法（`com.oplus.launcher`、`com.oppo.launcher`、`net.oneplus.launcher` 等）。
- **更省电**：系统事件合并窗口 50ms → 250ms；每次进入 App 只在前 12 秒响应内容变化事件（原来 25 秒）；扫描最小间隔 130ms → 300ms；单次扫描节点上限 2000 → 800；列表容器整棵子树直接剪枝；点中按钮后静默 1.5 秒；修掉「事件太密时定时器被无限推迟、结果一次都没扫」的防抖 bug；DNS 上游 IP 预解析、读缓冲复用。
- **自定义图标**：自适应图标（`mipmap-anydpi-v26`）+ 各密度兜底 PNG，不再是系统默认小机器人。
- **`rules.json` 升到 version 4**：新增「5s | 跳过」「5 跳过」「skip 5s」这类倒计时文案正则、更多 `skipIds`，以及一加 / ColorOS（heytap）自带 App 的开屏规则（`splashOnlyMs`）。
- **无障碍服务声明 `android:isAccessibilityTool="true"`**：按 Android 17 的要求把本服务声明为无障碍工具，系统「高级保护」开着时才有机会继续工作（仅声明不保证一定被系统认定；副作用见「Android 17 高级保护」一节）；主界面品牌识别分「三星 / 一加 / 未适配」三档，并提供「本 App 应用详情」「自启动 / 耗电管理」两个一键跳转按钮（另有一键「忽略电池优化」）。

三层机制（③ 可选），都在本机跑。不采集、不上传（DNS 层只把域名查询转发给硬编码的公共 DNS）：

| 层 | 技术 | 干什么 | 省电 |
|---|---|---|---|
| ① 无障碍自动点击 | `AccessibilityService` | 读到「跳过 / 跳过 5s / 关闭」就点一下，干掉开屏广告和应用内弹窗 | 事件驱动：只在 App 刚进前台那 12 秒里响应内容变化事件，其余时间零动作 |
| ② 本地 DNS 拦截 | `VpnService` + 本地 DNS 代理 | 只把 DNS 查询接下来，命中广告域名就回 NXDOMAIN，广告资源加载失败 | 只碰 DNS 包，不代理网页流量 |
| ③ 通知清理（可选） | `NotificationListenerService` | 清掉你指定包名的广告推送 | 事件回调，零轮询 |

> 版本：当前是 **v1.2**（versionCode 3）。上一版 v1.1 修的是「信息流 App 误点」，见下面「误点 / 误跳」一节；v1.2 适配了一加（ColorOS / OxygenOS），并做了一轮省电优化、换了图标。

## 先说清楚：能跳什么、跳不了什么

**能跳（效果好）**
- 开屏广告：主流 App 里带「跳过 / 跳过 5s」原生按钮的，绝大部分能自动跳过
- 应用内插屏、弹窗、"以后再说 / 残忍离开 / 我知道了"
- 一加 / ColorOS（heytap）自带 App 的开屏（v1.2 内置了专属规则）
- 广告推送通知（要手动填包名）

**跳不了（物理上做不到，别指望）**
- 信息流 / 原生广告（微博、淘宝、抖音、知乎里混在内容里的）
- 游戏内广告（Unity Ads、AppLovin 这类引擎自绘的），只能靠 DNS 层让它加载失败
- 视频贴片广告（爱奇艺、腾讯视频、优酷、YouTube）
- 用 Canvas / Flutter / SurfaceView 自绘、无障碍树里根本没有文字节点的广告（这种「跳过」按钮在系统眼里不存在）

**能做到多少**：日均最烦人的开屏广告，实测同类工具能干掉 70~85%，看具体 App。**"清掉所有广告"的 App 不存在。**

# 误点 / 误跳（v1.1 重点修的就是这个，v1.2 沿用）

**贴吧为什么会被误点**（v1.0 的真实 bug，已修）：
1. 旧规则的 `skipPatterns` 里有 `"^广告$"`。贴吧信息流里每条广告卡都带一个「广告」小标签，两个字正好整条匹配 → 点它的可点父控件就是整张卡片 → 直接进广告。
2. `^跳过` 允许 24 个字，且不看控件在哪。帖子里「跳过新手教程…」这类标题、楼层回复都在匹配范围内 → 一点就进帖子。
3. 点击时会向上爬 3 层父控件、且不限大小。开屏广告常把「跳过」和整块广告放在同一个可点容器里 → 爬到父容器点 = 点了广告本身，于是「跳过了」却进了广告落地页。

**闲鱼为什么也会被点进去**（同一个 bug）：
闲鱼的推荐流里有「广告」标记的商品卡，它**确实没有关闭叉号**——它本来就不是拿来关的。旧规则把「广告」两个字当成跳过按钮，点了标记牌，父控件就是那张卡片，于是直接跳进广告 / 商品页。没有叉号可点是正常的，问题在于「不该去点它」，现在这类卡片一律不点。

**v1.1 加了这些护栏**（都在 `AdSkipService.kt`，全部默认生效，不需要设置）：

| 护栏 | 干什么 |
|---|---|
| 按钮尺寸上限 | 目标超过屏幕 6% 面积 / 70% 宽 / 25% 高就一律不点（整块广告、卡片都过不了） |
| 列表容器识别 | 控件祖先里有 `RecyclerView / ListView / GridView`，或铺满大半屏、能滚、挂着一堆条目的容器 → 当信息流内容，直接放过（ViewPager 故意不算，开屏广告的素材轮播就在它里面） |
| 先点按钮自己 | 「跳过」自己可点就点自己；不可点就在它中心戳一下；**不再为了点它去爬整块广告的父容器** |
| 同位置冷却 | 同一坐标 6 秒内不重复点 |
| 点击配额下调 | 每个窗口最多 4 次（原来 8 次），误点也连不起来 |
| 去掉 `"^广告$"` | 「广告」是标签不是按钮，点了只会打开广告 |
| 贴吧 / 闲鱼专属时间窗 | `rules.json` 里给 `com.baidu.tieba`、`com.taobao.idlefish` 设了 `splashOnlyMs: 15000`：只在**进入该 App 后的前 15 秒**内工作（切走再切回来会重新计时），之后刷帖子 / 刷商品完全不介入 |

**代价（说清楚）**：这两个 App 的 `splashOnlyMs` 只在每次进入后的前 15 秒工作，所以**刷内容过程中弹出的插屏广告不会被自动关**。这是拿「少关几个弹窗」换「绝不点进你的帖子和商品」，我觉得值；不想要可以删掉 `rules.json` 里 `apps` 下对应的那一段。

**还误点怎么办**：
1. 点「上次扫描结果」，如果显示「命中过按钮但…在列表容器里 / 尺寸不像按钮 → 已主动放过」，那是护栏在正常工作；
2. 点「查看日志」，找 `[GUARD]`（放过了什么）和 `[CLICK]`（真点了什么）两行，把**那个 App 的包名 + 那几行**发我；
3. 临时救命：把这个包名填进「不处理的应用（黑名单）」，那个 App 立刻完全不动。

# 第一步：拿到 APK（不用装 Android Studio）

你电脑上没有 Android 编译环境，所以用 GitHub 的免费云构建。整个流程只需要浏览器，大概 10 分钟。

### 1. 注册 / 登录 GitHub
打开 https://github.com ，有账号直接登录，没有就注册（免费）。

### 2. 建一个仓库
- 右上角 `+` → **New repository**
- Repository name 填 `AdSkipper`
- 选 **Private**（私有，别人看不到）或 Public 都行
- **不要**勾 "Add a README file"
- 点 **Create repository**

### 3. 上传源码
- 把本目录（`AdSkipper` 文件夹）里的这些东西，**全部**拖进浏览器的上传框：
  `app` 文件夹、`settings.gradle.kts`、`build.gradle.kts`、`gradle.properties`、`README.md`
- 页面提示 "uploading your files" 后点 **Commit changes**

### 4. 单独创建构建脚本（关键一步）
浏览器的拖拽上传会**忽略以 `.` 开头的隐藏目录**，所以 `.github` 必须手动建：

- 仓库页点 **Add file** → **Create new file**
- 文件名输入：`.github/workflows/build.yml`
- 用记事本打开本地的 `.github/workflows/build.yml`，**全选复制**，粘贴到网页编辑框
- 点 **Commit changes**

### 5. 跑构建
- 点仓库顶部的 **Actions** 标签
- 左边点 **Build APK** → 右边 **Run workflow** → 绿色 **Run workflow**
- 等 2~4 分钟，列表里出现绿色 ✓

### 6. 下载 APK
- 点进那次绿色 ✓ 的运行记录
- 拉到页面最底部 **Artifacts** 区域 → 下载 **AdSkipper-apk.zip**
- 解压，里面就是 `app-debug.apk`（约 1~2 MB）

> 以后我改了代码，你重新上传/替换文件，再跑一次 Actions 就行。
> 工作流里缓存了签名文件，所以**新版本可以直接覆盖安装、不会丢设置**。

**Plan B（GitHub 上不去的时候）**
- 找一个装了 Android Studio 的朋友：`File → Open` 选这个文件夹，点 Run 就能出 APK；
- 或者把这堆文件给手机维修店/会安卓开发的人，同样的操作用 5 分钟。

# 第二步（A）：三星（One UI）安装步骤

### 1. 先关掉「自动拦截器」
One UI 6.1 以后默认拦截侧载安装的 App。

`设置 → 安全与隐私 → 自动拦截器` → 关掉（装完可以再打开）

### 2. 安装 APK
把 `app-debug.apk` 传到手机（微信文件传输助手 / USB / 网盘），点开安装。
提示"未知来源应用"时允许一次即可。

### 3. 允许「受限设置」（Android 14+ 必须，否则开不了无障碍）
`设置 → 应用 → 跳过广告 → 右上角 ⋮ → 允许受限设置`

侧载 App 的无障碍、通知使用权默认是被系统锁住的，不点这个开关，后面两步永远开不起来。

### 4. 开无障碍服务
App 里点 **① 去开启「无障碍服务」**，或者手动：
`设置 → 辅助功能 → 已安装的服务 → 跳过广告 → 打开`

打开时系统会弹「此服务可以查看屏幕内容」的警告，确认即可。

### 5.（可选）DNS 拦截层
App 里打开 **「开启 DNS 拦截」**，系统会弹 VPN 授权，同意。

先做两件事，否则它不生效：
- `设置 → 连接 → 更多连接设置 → 私人 DNS` → 改成 **关闭**
  （私人 DNS 会走 DoT 绕过 VPN 的 DNS，开着它 DNS 拦截就是废的）
- 确认没有别的 VPN / 代理 / 梯子在跑（安卓同一时间只允许一个 VPN）
- 开完点 App 里的 **「查看 DNS 拦截统计」**，确认一次（很重要，见下文）

### 6.（可选）通知清理
- App 里打开「启用通知清理」，点 **② 打开「通知使用权」设置**，允许
- 在输入框里填要清理的包名，逗号隔开，比如：
  `com.xingin.xhs,com.taobao.taobao`
- 点「保存通知清理名单」

# 第二步（B）：一加（ColorOS / OxygenOS）安装步骤

> ColorOS / OxygenOS 各版本（13 / 14 / 15）的菜单名和层级略有差异，下面的写法以国内 ColorOS 14 / 15 为准。**找不到就用设置顶部的搜索框**，搜「应用管理 / 耗电管理 / 自启动 / 无障碍 / 私人 DNS / 安装未知应用」基本都能直达，别硬背路径。
>
> OPPO / realme 与一加同源，手机上大概率也能用，但**这一版只对一加做了适配、不保证**，出问题别当 bug 报。

### 1. 允许安装未知来源应用
`设置 → 应用 → 应用管理 → 右上角 ⋮（或「更多」）→ 特殊应用权限 → 安装未知应用` → 找到你用来传 APK 的 App（微信 / 文件管理 / 浏览器）→ 允许。

不同 ColorOS 版本菜单名略有差异，找不到就用设置顶部搜索「安装未知应用」。

### 2. 安装 APK
把 `app-debug.apk` 传到手机（微信文件传输助手 / USB / 网盘），点开安装。
ColorOS 会先做一遍安全检测并弹「风险提示 / 该应用未经安全审核」，选 **继续安装 / 仍要安装**，按提示允许一次即可。

### 3. 应用详情里放行后台（最重要）
打开 `设置 → 应用 → 应用管理 → 跳过广告`（或者长按桌面图标 → 应用详情 → 右上角 ⋮）：

- **耗电管理**：允许「**允许完全后台行为**」，并把「智能后台控制 / 睡眠模式」这类限制关掉
- **自启动**：允许「**允许自启动**」（部分版本在「应用 → 自启动管理」里单独列，需要在那边再勾一次）
- 如果列表里有「关联启动 / 后台弹出界面」，一并允许——跳广告要能读到别的 App 的前台窗口

> 不同 ColorOS 版本菜单名略有差异，找不到就用设置顶部搜索「耗电管理」「自启动」。

### 4. 锁定最近任务（防止被一键清理干掉）
打开「最近任务」→ 找到「跳过广告」卡片 → 长按 / 点卡片右上角 `⋮` → **锁定**（小锁图标）。

ColorOS 的「一键清理」默认会杀后台，锁定之后它就留在内存里。无障碍服务本身是系统托管的，但 DNS 层的 VPN 前台服务会被清理杀掉。

### 5. 关闭「私人 DNS」（只有开 DNS 层才需要）
`设置 → 连接与共享 → 私人 DNS`（部分版本在「其他无线连接」或「更多连接」里）→ 改成 **关闭**。

私人 DNS 会走 DoT 绕过 VPN 的 DNS，开着它 DNS 拦截就是废的。不开 DNS 层的话这步跳过。**找不到就用设置顶部搜索「私人 DNS」。**

### 6. 开无障碍服务
App 里点 **① 去开启「无障碍服务」**，或者手动：
`设置 → 系统设置（或「其他设置」）→ 无障碍 → 已安装的服务 / 已下载的应用 → 跳过广告 → 打开`

- 打开时系统会弹「此服务可以查看屏幕内容」的警告，确认即可
- ColorOS 可能额外弹「权限监控 / 敏感权限」之类的二次确认框，允许
- Android 14+ 侧载 App 还需要 **「允许受限设置」**：`设置 → 应用 → 应用管理 → 跳过广告 → 右上角 ⋮ → 允许受限设置`（不同版本入口略有差异，找不到用设置顶部搜索）

### 7.（可选）通知清理
和三星一样：App 里打开「启用通知清理」→ 点 **② 打开「通知使用权」设置** → 允许 → 填包名 → 保存。

### ColorOS 上无障碍被系统「弹回」怎么办
ColorOS 的权限监控 / 省电策略有时候会把侧载 App 的无障碍自动关掉，表现是：用一阵子突然不跳了，进设置一看开关是关的。按顺序排查：

1. `设置 → 应用 → 应用管理 → 跳过广告 → 耗电管理`，确认「允许完全后台行为」还开着，并且没被「智能省电」重新接管；
2. 关掉系统「权限监控 / 敏感权限提醒」对它的限制（不同版本名字不同，用设置顶部搜索「权限监控」）；
3. 最近任务里确认 App 还锁着，没被清理；
4. 重新打开无障碍开关（App 里点 ① 会直接跳到正确页面）；
5. 还是反复被关：把它加进「电池 → 更多设置 → 应用耗电管理」里的「不限制 / 允许后台高耗电」名单。

# 第三步：省电设置（重要，不做会被后台杀掉）

v1.2 主界面把这几件事做成了一键按钮：**「忽略电池优化」**、**「本 App 应用详情」**、**「自启动 / 耗电管理」**——点一下直接跳到系统对应页面（跳不过去会退回应用详情），不用自己翻菜单。各家 ROM 的入口名字不一样，跳过去之后按下面各机型的位置开关即可。

**三星（One UI）**
1. **加进「永不休眠的应用」**
   `设置 → 电池 → 后台使用限制 → 休眠应用` → 找到「跳过广告」→ 改为 **永不休眠**
2. **关掉「移除权限节省空间」**
   `设置 → 应用 → 跳过广告 → ⋮ → 管理空间/权限` → 关掉「不使用时移除权限」
3. **App 里点「忽略电池优化」** → 允许

**一加（ColorOS / OxygenOS）**
1. 应用详情 → **耗电管理** → 允许完全后台行为，关掉智能后台控制
2. `设置 → 应用 → 自启动管理` → 允许「跳过广告」自启动
3. App 里点「**忽略电池优化**」→ 允许（已经在「不受电池限制」名单里会提示）
4. 最近任务里锁定 App（见上一节第 4 步）

**通用**：无障碍服务本身是系统托管的，正常不会被杀；这些设置主要是防各家 ROM 的后台清理。

**实际耗电**：正常情况下接近 0（< 1%/天级别）。判断依据：不轮询、不唤醒、不持有 wake lock、没有 Alarm / JobScheduler / 定时器；只有别的 App 刚进前台那 12 秒里，系统把内容变化事件送给它，它才醒来扫一遍（扫完就睡）。

v1.2 又收紧了一轮：系统事件合并窗口 50ms → 250ms（原来每秒最多被叫 20 次）；响应窗口 25 秒 → 12 秒；两次扫描最小间隔 130ms → 300ms；单次扫描节点上限 2000 → 800；列表容器整棵子树直接剪枝；点中按钮后静默 1.5 秒。

> 如果你开了 DNS 层，它会常驻一个前台通知（VPN 图标）。那是系统要求，不能去掉。

# 怎么调规则（这就是为什么它不完美但能变好）

### 看日志
App 里点 **「查看日志」**：

```
12:31:02 [CLICK] com.taobao.taobao  跳过 跳过 5s  score=112
12:31:05 [MISS]  com.xxx.app  跳过 跳过  找到了但点不动
12:31:06 [GUARD] com.baidu.tieba  命中的【跳过 跳过新手教程】在列表容器里（像信息流内容）  已放过
12:31:20 [RULE]  规则已加载 v4：跳过 9 条，关闭 7 条，激进 11 条
```

- `[CLICK]` = 跳过成功
- `[MISS]` = 找到了按钮但点不动（这种要发我，我加手势兜底规则）
- `[GUARD]` = 命中过，但被防误点护栏放过了（尺寸不像按钮 / 在信息流列表里）。**这是好事**，说明护栏在替你挡住误点
- 没有日志 = 那个 App 的广告按钮在无障碍树里根本不存在（自绘广告，无解）
- `[RULE]` 行里的条数来自当前 `rules.json`，改规则 / 升版本后数字会变，不用对号入座

### 上次扫描结果
打开一个有开屏广告的 App，等广告出来，再切回本 App 点 **「上次扫描结果」**。它会告诉你：上一次对其他 App 的扫描看了多少控件、有没有命中、命中在哪个控件上。

- 显示「命中【跳过 xxx】」但还是没跳过 → 点不动，把日志发我
- 显示「扫描 N 个节点，没找到…」→ 那个 App 的广告按钮系统读不到（自绘广告），无解
- 显示「命中过按钮但…已主动放过（防误点）」→ 护栏挡住了，正常；如果它确实是个该点的跳过按钮，把这个 App 的包名发我，我调尺寸/列表判断

（说明：不能在广告显示时"现场检测"，因为一切回本 App，广告页就已经不在前台了。所以这里看的是"上次扫描"的记录。）

### 自己加规则
改 `app/src/main/assets/rules.json`：

```json
{
  "version": 4,
  "skipPatterns": [
    "^跳过",
    "跳过.{0,8}(广告|\\d+\\s*[s秒S])",
    "^\\d{1,2}\\s*[sS秒]?\\s*[|｜/·]?\\s*跳过\\s*[>》]?$",
    "^skip\\s*\\d+\\s*[sS]?$"
  ],
  "closePatterns": ["^关闭广告$"],
  "aggressiveClosePatterns": ["^关闭$", "^×$"],
  "skipIds": ["btn_skip", "splash_skip", "tt_splash_skip_btn", "ksad_skip_view"],
  "apps": {
    "com.example.app": {
      "skipPatterns": ["^跳过广告"],
      "splashOnlyMs": 15000
    },
    "com.heytap.example": {
      "splashOnlyMs": 8000
    }
  },
  "launchWindowMs": 12000
}
```

**注意：JSON 里不能写 `//` 注释**——写了整个文件解析失败，所有规则会静默失效（App 看起来「正常工作但什么都不跳」）。字段含义写在这里：

- `skipPatterns`：高置信度，文字是「跳过」类，任何时候都点（≤16 字）；
- `closePatterns`：中置信度，只在本次进入 App 后的前 `launchWindowMs`（默认 12 秒）内点，且必须可点；
- `aggressiveClosePatterns`：低置信度，只有开了「激进模式」才点；
- `skipIds`：控件 id 里包含这些字符串就点（全小写比较）；
- `apps`：给单个 App **追加**规则（和全局规则取并集，不会覆盖或缩小全局）；`splashOnlyMs` = 进入该 App 后只在前 N 毫秒内工作；
- 正则里的反斜杠在 JSON 里要双写：正则的 `\d` 在文件里写成 `\\d`。

两条经验（都是踩过的坑）：
- **不要往 `skipPatterns` 里加「广告」这种纯标签词**。信息流里每条广告卡都有「广告」标签，点了等于点进广告；
- 某个 App 属于「刷内容型」（贴吧、微博、知乎这类），而它的广告基本只在冷启动出现，就给它加 `splashOnlyMs`——刷内容时完全不介入，从根上不可能误点。

改完重新上传、重新跑 Actions、覆盖安装。

### 激进模式（默认关）
主界面有个「激进模式」开关。关着时只点高置信度的广告关闭按钮（`关闭广告 / 残忍离开 / 以后再说 / 直接进入`）；打开后会额外点 `关闭 / × / 我知道了 / 不感兴趣` 这类通用按钮。

**建议**：先用默认的关着，发现哪个 App 的弹窗关不掉，再打开激进模式试。开着它误点概率明显上升（比如把某个正常的确认弹窗关掉），这也是为什么它默认关闭、并且黑名单要认真填。

### 加黑名单（防误点）
主界面底部「不处理的应用」填包名，逗号隔开。**银行、支付、证券类强烈建议加进去**：这类 App 里有大量"关闭""确认"，宁可让它弹广告，也别让工具乱点。

# DNS 层的取舍（自己决定开不开）

**先说风险**：这一层用的是「只路由 DNS 的 VPN」（不抓全流量），靠系统把 DNS 查询优先送给 VPN 的 DNS 服务器来实现拦截。这是 DNS66 / personalDNSfilter 那类工具的路子，在多数机型上成立，但**在个别 ROM / 系统版本上可能完全不生效**，而且我这边没有真机可以替你验证。

所以：**开完用几分钟手机，再点 App 里的「查看 DNS 拦截统计」**。它显示的是 tun 里真实收到/拦截了多少条 DNS 查询——这是唯一可靠的判据（不能用"在本机 ping 一下域名"来测，因为本 App 自己被排除在 VPN 之外，测得不准）。

- 「收到查询」是 0 → 这层在你机器上没打通，**直接关掉 DNS 开关**，只用无障碍层；
- 收到几百条、命中几条 → 正常工作；
- 想重新观察就先点「清零重计」，刷几个 App 再回来看。

**好处**：能从源头减少一批 banner / 插屏 / 激励视频的广告资源，顺带减少跟踪统计。

**代价**：
1. 占用系统 VPN 通道 → **和公司内网 VPN、代理工具冲突**，二选一；
2. `私人 DNS` 必须**关闭**（不能是"自动"，DoT 会绕过 VPN）——三星在 `设置 → 连接 → 更多连接设置`，一加在 `设置 → 连接与共享`，找不到就在设置顶部搜索「私人 DNS」；
3. 黑名单里某个域名可能同时被正常功能使用 → 表现为某 App 图片加载不出、分享失败、推送延迟。**出现这种情况先关掉 DNS 层**，然后从 `blocklist.txt` 里把可疑域名注释掉；
4. 广告 SDK 加载失败时，有的 App 会弹"网络连接失败"或白屏一会儿，属正常；
5. 首次启动时如果反复拨开关，可能看到 VPN 图标闪一下——正常。

**如果你只想用①层**，DNS 层完全不用开，跳开屏广告照样工作。

# Android 17 高级保护（v1.2 为什么加了 `isAccessibilityTool`）

Android 17 新增了「高级保护」模式。开启后，只有被系统认定为「无障碍工具」的应用才允许调用无障碍 API；官方要求这类服务在自己的配置里声明 `android:isAccessibilityTool="true"`，没声明的应用会被掐掉，表现就是「无障碍开关打开了，但完全没反应」。v1.2 已经在无障碍服务配置（`res/xml/accessibility_service_config.xml`）里补上这个声明。

**但要说明白**：只加这个 flag 不等于一定通过系统认定（系统还会看用途、分发渠道等，通用去广告类 App 未必被算作无障碍工具）。所以最稳的用法是：开了高级保护后发现无障碍不工作，先去 `设置 → 安全与隐私 → 高级保护` 把它关掉再试。Android 17 的本 App 主界面也会显示这条提示。

**说清楚副作用（你需要知道）**：

- 声明成 `isAccessibilityTool="true"` 之后，系统会把它当成「受信的无障碍工具」——这意味着它在技术上**有能力读取密码框等敏感界面的文字**（这是无障碍 API 本身的权限范围，不是本 App 额外申请的权限）。
- 本 App 只做一件事：把当前屏幕里的按钮文字读出来做正则匹配，命中「跳过 / 关闭」就点一下。**不采集、不记录、不上传任何内容**；日志只存在内存里（最多 400 条，重启就没），DNS 层只解析域名、只转发。
- 不想让它看到敏感界面：把银行 / 支付 / 密码管理器 / 证券 App 的包名填进「不处理的应用（黑名单）」，它对那些包名完全不介入。

**怎么看自己开没开**：`设置 → 安全与隐私 → 高级保护`（不同版本入口名字不同，用设置顶部搜索「高级保护」）。注意：开着高级保护后，**没做这个声明的无障碍工具基本都会失效**，不只是本 App——如果别的辅助工具突然不能用了，先来这里看一眼。

# 常见问题

**Q: 开了无障碍，但某个 App 广告完全没反应？**
A: 绝大多数是自绘广告（Flutter / 游戏引擎 / Canvas），系统读不到按钮。这种只能靠 DNS 层让它加载不出来。用「上次扫描结果」确认一下，如果显示"没找到可点的跳过/关闭按钮"，就是这种。

**Q: 一加上明明开着无障碍，过一阵又不跳了？**
A: 多半是被 ColorOS 的权限监控 / 省电策略自动关掉了（侧载 App 常见）。按「ColorOS 上无障碍被系统弹回怎么办」那 5 步处理：确认耗电管理还是「允许完全后台行为」、解除权限监控限制、最近任务锁定、重新打开无障碍开关、加进「不限制」耗电名单。

**Q: 开了 Android 17「高级保护」还能用吗？**
A: 本 App 已按官方要求声明了 `android:isAccessibilityTool="true"`，正常情况下能继续用；但「高级保护」的放行名单由系统判定，**不保证一定放行**——真遇到无障碍不工作，先去 `设置 → 安全与隐私 → 高级保护` 关掉它再试。额外权限范围见「Android 17 高级保护」一节，介意的话用黑名单把敏感 App 排除掉。

**Q: DNS 统计显示「收到查询 0 条」怎么办？**
A: 说明「只路由 DNS 的 VPN」这个套路在你的机器 / 系统版本上没打通（这是个真实存在的兼容性风险，我这边没有真机替你验证）。处理办法：直接把 DNS 开关关掉，只用无障碍层，跳开屏广告照样工作。别为了一个没生效的功能白占 VPN 通道。

**Q: 会不会误点到别的东西？**
A: 设计上有多重保护：只匹配「跳过/关闭」这类短文字（≤16 字）、只点窗口出现后 12 秒内的关闭类、**只点按钮尺寸的控件（超过屏幕 6% 面积一律不点）**、**列表容器（RecyclerView/ListView/GridView 等）里的文字一律放过**、**点「跳过」时点按钮自己而不是包着它的整块广告**、避开系统界面/输入法/桌面/本 App、每个窗口最多点 4 次、两次点击间隔 ≥320ms、同一位置 6 秒内不重复点。但**任何自动点击工具都有极小概率误点**，所以黑名单功能建议认真用。

**Q: 会不会耗电/卡顿？**
A: 不会。没有轮询、没有常驻线程池、没有 wake lock、没有 Alarm / JobScheduler / 定时器。扫描放在独立后台线程，每个 App 刚进前台后的前 12 秒里才响应内容变化事件（系统事件还做了 250ms 合并）。真实数字见「第三步：省电设置」里的「实际耗电」。

**Q: 会不会有隐私问题？**
A: 权限只有 5 条，逐条列在上面「安全与权限边界」里——没有定位、通讯录、短信、通话、存储、相机、麦克风、悬浮窗、设备标识，也没有任何第三方 SDK。屏幕文字只在内存里做正则匹配，**不保存、不截图、不上传**；日志最多 400 条且只在内存。v1.2 给无障碍服务声明了 `isAccessibilityTool`，系统会把它当受信工具，技术上能读到密码框之类的敏感界面——不想让它碰，就把银行 / 支付 / 密码管理器包名填进黑名单，它对这些包名完全不介入。

**Q: 为什么不做 root 版？**
A: 因为 S24+ 解锁 bootloader 会**永久熔断 Knox（eFuse）**：Samsung Pay / 钱包、Secure Folder、Samsung Pass、多数银行 App 直接报废，保修也没了。为了拦信息流广告付这个代价不值。一加同理：解锁 bootloader 会失去保修，部分银行 / 支付 App 的风控也会升级。root 版能做到更多（hook 广告 SDK 直接返回"无广告"），但那是给备用机玩的。

**Q: 升级新版本要卸载吗？**
A: 不用，工作流缓存了签名。万一缓存被 GitHub 清掉了导致签名变了，安装时会报"应用未安装"，卸载旧版重装即可（设置会丢）。
